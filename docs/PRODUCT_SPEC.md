# Product Specification

> Status: Draft. 기능을 구현하면서 암묵적으로 결정하지 말고, 중요한 선택은 이 문서에서 먼저 명시합니다.

## 1. Product statement

현재 임시 정의:

> 놀히스토리는 역사적 사건·인물·시대·장소의 관계를 탐색하며 맥락을 이해하도록 돕는 학습 웹 서비스다.

이 문장은 핵심 경험이 확정되면 수정합니다.

## 2. Primary users

아직 확정하지 않음.

검토할 후보:

- 초등학생 개인 학습
- 교사 수업 제시/탐구 활동
- 교사와 학생이 함께 사용하는 교실 활동
- 일반 사용자의 역사 탐색

**결정 필요:** 첫 버전의 1순위 사용자를 하나로 고정할 것.

## 3. Core user job

아직 확정하지 않음.

후보 질문:

- 시대 흐름을 이해하는가?
- 사건의 원인과 결과를 연결하는가?
- 인물의 선택을 맥락 속에서 탐구하는가?
- 역사 속 생활 모습을 비교하는가?
- 지도와 연표를 통해 시간·공간 관계를 파악하는가?
- 분기형 이야기처럼 역사 상황을 체험하는가?

## 4. Candidate content entities

초기 데이터 모델 후보이며 아직 확정 스키마가 아닙니다.

- Period / Era
- Event
- Person
- Place
- Object / Artifact
- Topic
- Source
- Media asset
- Learning activity

각 엔터티는 화면 컴포넌트와 독립된 데이터로 유지하는 것을 원칙으로 합니다.

## 5. Source metadata

역사적 주장 또는 콘텐츠 단위는 필요에 따라 다음을 추적할 수 있어야 합니다.

- source title
- institution / author
- source type
- URL or bibliographic reference
- accessed/reviewed date
- claim supported
- confidence / dispute note
- reviewer note

사용자 화면에 모든 메타데이터를 노출할 필요는 없지만 내부 추적은 가능해야 합니다.

## 6. UX principles

- 첫 화면에서 서비스 목적과 시작 행동이 분명해야 한다.
- 정보량이 많아도 한 화면에 모두 펼치지 않는다.
- 학습자는 현재 **언제·어디·누구·무슨 일**을 보고 있는지 잃지 않아야 한다.
- 탐색 중 이전 맥락으로 쉽게 돌아갈 수 있어야 한다.
- 읽기만 하는 화면보다 비교·연결·선택·확인 같은 능동 행동을 우선 검토한다.
- 어린 학습자에게 불필요한 전문 용어는 줄이되 핵심 개념은 삭제하지 않는다.

## 7. Open decisions

구현 전에 우선 결정할 항목:

1. 놀히스토리의 핵심 경험 한 가지
2. 첫 콘텐츠 범위
3. 주요 사용자
4. 기본 탐색 구조
5. 연표/지도/이야기/카드 중 중심 인터페이스
6. 콘텐츠 제작자가 누구인지
7. 사용자 생성 콘텐츠가 필요한지
8. 저장/공유/로그인이 실제로 필요한지
9. AI가 사용자에게 직접 콘텐츠를 생성하는지, 제작 보조에만 쓰이는지

## 8. Decision rule

새 기능은 다음 세 질문 중 최소 하나에 명확히 답하지 못하면 보류합니다.

- 역사 맥락 이해가 더 좋아지는가?
- 탐구 행동이 더 좋아지는가?
- 교사/학습자의 실제 작업이 줄어드는가?
